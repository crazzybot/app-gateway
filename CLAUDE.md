## Project Overview

The **App Gateway Service** is the single front door for all platform traffic. It provides:

- **Unified Authentication** — JWT issuance, refresh, and revocation backed by Redis.
- **Single Sign-On (SSO)** — SAML 2.0 identity-provider integration via `passport-saml`.
- **OAuth 2.0** — Full Authorization Code flow (with mandatory PKCE), Client Credentials, and Token Introspection.
- **Reverse Proxy** — Path-based routing to upstream micro-services via `http-proxy-middleware`.
- **Rate Limiting & Security Headers** — Express-level guards applied before any upstream call.

Specs live in:
- `@specs/app-gateway-auth.spec.md`
- `@specs/openapi.yaml`

## Architecture Overview

| Layer | Technology |
|---|---|
| **HTTP layer** | Express 5 (`express@^5`) |
| **Auth (JWT)** | `jose` — JWKS-backed RS256 / ES256 signing & verification |
| **Auth (SAML)** | `passport` + `passport-saml` |
| **Reverse Proxy** | `http-proxy-middleware` |
| **Cache / Token Revocation** | Redis via `ioredis` |
| **Database** | PostgreSQL via Drizzle ORM (`drizzle-orm` + `pg`) |
| **Input Validation** | `zod` — every external boundary |
| **Logging** | `winston` (JSON in prod, pretty in dev) |
| **Testing** | `vitest` + `supertest` |

## Coding Conventions

### TypeScript
- **Strict mode is mandatory** — `strict: true` in `tsconfig.json` with no overrides.
- **Never use `any`** — use `unknown` and narrow with Zod or type guards. ESLint will error on `any`.
- All public functions must have explicit return type annotations.
- Prefer `type` over `interface` for object shapes; use `interface` only when declaration merging is intentional (e.g., `express.d.ts`).

### Validation
- **Zod for every external input boundary**: route params, query strings, request bodies, environment variables, upstream service responses, and file-based config (e.g., `UPSTREAM_SERVICES_CONFIG_PATH`).
- Parse once at the edge; pass typed values inward — never re-validate inside services.

### Error Handling
- All service functions return `Result<T, AppError>` (see `src/types/result.ts`).
- Route handlers unwrap the Result and call `next(err)` on failure.
- The global error handler (`src/middleware/errorHandler.ts`) maps `AppError` subclasses to HTTP status codes.
- **Never swallow errors** — always propagate or log with full context.

### Database
- **No raw SQL** — use the Drizzle query builder exclusively.
- Schema lives in `src/db/schema.ts`; migrations are generated (`drizzle-kit generate`) and applied separately (`drizzle-kit migrate`).
- Use transactions for any multi-step write; pass the transaction object (`tx`) into service helpers.

### Logging
- Use the `logger` singleton from `src/config/logger.ts` — never `console.log`.
- Log level is controlled by `LOG_LEVEL` env var.
- Every request gets an `X-Request-ID`; include it in all log entries for that request.

### Style
- 2-space indentation, single quotes, trailing commas (ESLint + Prettier enforce this).
- Import order: Node built-ins → third-party → internal (`src/`). Use path aliases (`@/`) for internal imports.

## Environment Variables

All variables are validated at startup by `src/config/env.ts` using Zod.  
The service **will not start** if a required variable is missing or malformed.

| Variable | Required | Description |
|---|---|---|
| `PORT` | No (default `3000`) | HTTP listen port |
| `NODE_ENV` | Yes | `development` \| `production` \| `test` |
| `DATABASE_URL` | Yes | PostgreSQL connection string (`postgres://...`) |
| `REDIS_URL` | Yes | Redis connection string (`redis://...`) |
| `JWT_PRIVATE_KEY_PATH` | Yes | Absolute path to PEM private key for JWT signing |
| `JWT_PUBLIC_KEY_PATH` | Yes | Absolute path to PEM public key (or JWKS JSON) |
| `JWT_ALGORITHM` | No (default `RS256`) | `RS256` \| `RS384` \| `ES256` \| `ES384` |
| `ACCESS_TOKEN_TTL_SECONDS` | No (default `900`) | Access token lifetime in seconds |
| `REFRESH_TOKEN_TTL_SECONDS` | No (default `2592000`) | Refresh token lifetime in seconds (30 days) |
| `SAML_SP_ENTITY_ID` | Yes* | Service-provider entity ID (*required if SAML enabled) |
| `SAML_SP_CALLBACK_URL` | Yes* | ACS callback URL (`https://…/v1/auth/saml/callback`) |
| `UPSTREAM_SERVICES_CONFIG_PATH` | Yes | Path to JSON file describing upstream routing table |
| `RATE_LIMIT_WINDOW_MS` | No (default `60000`) | Rate-limit sliding window in milliseconds |
| `RATE_LIMIT_MAX_REQUESTS` | No (default `100`) | Max requests per window per IP |
| `LOG_LEVEL` | No (default `info`) | `error` \| `warn` \| `info` \| `debug` |

See `.env.example` for a complete template.

## Testing Rules

| Scope | Command | Notes |
|---|---|---|
| Unit | `npm test` | `vitest run` — fast, no I/O, runs in CI on every PR |
| Integration | `npm run test:integration` | `vitest run --config vitest.integration.config.ts` |
| Coverage | `npm run test:coverage` | Fails if total < 80% |
| Type-check | `npm run typecheck` | Runs before every test suite in CI |

### Rules
1. **All new code must achieve ≥ 80% line/branch coverage** — measured by `@vitest/coverage-v8`.
2. **Integration tests use real services** — spin up PostgreSQL and Redis via **Testcontainers** (`testcontainers` npm package). Never mock the database or Redis in integration tests.
3. Unit tests may mock `ioredis` and `pg` with `vi.mock(...)`.
4. Each test file imports from `@/` aliases — never from `../../..` relative paths.
5. Test files live next to the scope they cover: `tests/unit/token.service.test.ts`, etc.
6. Use `supertest` for HTTP-layer tests; import the `app` export from `src/index.ts` — do **not** call `app.listen()` in tests.

## Security Rules

> Violations of these rules are **blocking** — PRs will not be merged.

1. **Never log access tokens, refresh tokens, client secrets, or passwords** — not even partially.  
   Audit events reference token JTI (ID) only.
2. **Rotate signing keys without downtime** — the JWKS endpoint (`/v1/oauth/jwks`) must serve both the active key and the previous key during the rotation window. Key IDs (`kid`) must be stable UUIDs.
3. **Validate all SAML assertions** — verify signature, `NotBefore`/`NotOnOrAfter` time windows, audience restriction, and destination URL. Reject unsigned assertions unconditionally.
4. **Enforce PKCE on every OAuth `authorization_code` flow** — `code_challenge` (S256 only) is required at `/v1/oauth/authorize`; `code_verifier` is required at `/v1/oauth/token`. Plain challenge method is rejected.
5. **`Secure; HttpOnly; SameSite=Strict`** on all cookies that carry tokens.
6. All routes behind `/api/**` must pass JWT authentication middleware before proxying — no anonymous upstream calls unless explicitly allow-listed in the upstream config.
7. Helmet is applied globally; do not disable any Helmet default.
